# 1. DATA FORMAT (customer app, v222)

Everything lives in one object `S`, saved as JSON in localStorage key `proview-bookings-v1`. Two more small keys: `proview-bookings-v1-colors` = `{"main":"#3f5fd0","bg":"#f2f4f9"}` (colour theme) and `proview-bookings-v1-theme` = `"light"` or `"dark"`.

Top-level fields of `S`:
| Field | Type | Meaning |
|---|---|---|
| venue | object | name, opening hours, stay lengths, and `id` (see Venue) |
| tables | array of table | all tables, all rooms |
| rooms | array of string | room names, in tab order, e.g. `["Main room","Terrace"]` |
| deco | array of decor item | walls, bar, doors, plants, labels |
| parties | array of booking | every booking, past and future (field is called `parties`) |
| waiting | array of waitlist entry | walk-in queue |
| gnotes | object string to string | guest notes, keyed by guest key |
| ts | object table id to string | live table status |
| auto | number | auto-complete minutes, 0 = off |
| fc | object | labour and forecast settings |
| hist | object | imported or sample daily history |
| histSample | boolean | true if `hist` is generated sample data |
| staff | array of staff member | people who can punch in (see Staff, punches, breaks) |
| punches | array of punch | every clock-in and clock-out, with breaks |
| rotaSh | array of rota shift | **new**, shifts from an uploaded rota (see Rota) |
| loy | object | **new**, loyalty scheme settings and redemptions (see Loyalty) |
| mgrPin | string | **new, SENSITIVE.** Manager PIN (4 to 6 digits, plain text). Never export. Empty or missing = not set yet |
| demoY, demoU, demoP | number (1) | flags: sample "yesterday", "upcoming" and staff/punch data already added |

**Booking** (in `S.parties`)
| Field | Type | Notes / example |
|---|---|---|
| id | string | random, e.g. `"k3j9x2a"` |
| name | string | `"Ella Brooks"` |
| phone | string | `"07700 900131"` (may be empty) |
| email | string, optional | **new.** `"ella@example.com"`. Used only to email a loyalty reward code. Latest non-empty email for a guest key is used |
| size | number | party size, `4` |
| date | string | `"2026-11-05"` (YYYY-MM-DD, local date) |
| time | string | `"19:00"` (HH:MM, 24h) |
| dur | number | stay length in minutes, `90` (set from venue rules, editable) |
| table | string | table id, or `""` when no table allocated |
| status | string | one of `booked`, `seated`, `done`, `noshow`, `cancelled` |
| notes | string | booking note for this visit, `"Birthday, cake at 20:00"` |
| tags | array of string | any of `VIP`, `Regular`, `Allergy`, `Celebrating` |
| src | string | one of `Phone`, `Website`, `Walk-in`, `App` |
| arr | boolean, optional | guest has arrived (still `booked`, not yet seated) |
| resolved | boolean, optional | past-due booking was checked off by staff |
| left | number, optional | **new.** ms timestamp, set ONLY when staff press **Left** on a seated booking. This is the restaurant's confirmation that the visit happened. Cleared on Reopen |
| disc | number, optional | **new.** loyalty discount percent applied to this booking, e.g. `10` |
| code | string, optional | **new.** reward code used for that discount, e.g. `"PV-0W2BO"` |

Rules: end time = time + dur. Large parties (size at or above `venue.bigFrom`) default to `venue.bigDur`. A booking is "unresolved" if it is still `booked`, past its end time, not `resolved`, and within the last 2 days. Table allocation conflicts are checked by time overlap on the same table.

**Seated / Unseat / Left (Tables and Bookings pages)**
- **Seated:** the earliest `booked` booking today on that table becomes `seated` and `arr` is set. Table status becomes `seated`.
- **Unseat:** guest was seated by mistake, or came back to reception. The booking goes back to `booked` (keeps `arr: true`), **keeps its table**, and the table status becomes `free`. It is not unassigned. To remove the table, use "Remove table".
- **Left:** the only action that closes a visit. Booking becomes `done` with `left` set, table status becomes `clearing` ("Needs clearing").
- Left, Unseat and the status buttons show for any table that is tapped. `done` set any other way (auto-complete, Complete on a past-due booking, editing the status) does **not** set `left`.

**Guest.** There is no stored guest record. Guests are worked out from bookings. A guest's key is `(phone || name).toLowerCase()`, e.g. `"07700 900131"` or `"ella brooks"`. The only stored guest data is the guest note: `S.gnotes["07700 900131"] = "Manager's friend, regular"` (string), and the loyalty redemption count in `S.loy.used`. Visits, no-shows and last visit are counted from bookings with that key. Editing a guest (name, phone, email, note) updates all their bookings.

**Waitlist entry** (in `S.waiting`): `{"id":"w1","name":"Leo Edwards","size":4,"at":1793900000000,"quote":20,"notified":true}`. `at` = ms timestamp when added, `quote` = quoted wait in minutes, `notified` optional boolean. **New alert flags (optional):** `ack` (alert dismissed), `snz` (ms timestamp the alert is snoozed until, 5 minutes), `alr` (alert already sounded).

**Waiting-time alert (new):** when `quote > 0`, the party has waited longer than `quote`, and it is not `notified`, `ack` or snoozed, a pop-up shows on every page (Seat now, Snooze 5 min, Dismiss) with a short beep and vibration. Checked every 15 seconds. Only works while the app is open.

**Table** (in `S.tables`)
| Field | Type | Notes |
|---|---|---|
| id | string | random |
| name | string | `"T6"` |
| seats | number | 1 to 24 |
| area | string | **the room name** (field is called `area`, not `room`), `"Terrace"`. Missing means `"Main room"` |
| shape | string, optional | `round`, `square` or `rect`. If missing: 2 seats or fewer is round, otherwise rect |
| x, y | number, optional | position in pixels inside the room's plan, `x:190,y:20` |
| w, h | number, optional | size in pixels, `w:116,h:70`. If missing, derived from seats (2: 64x64, 4: 88x70, 6: 116x70, more: 144x70) |

Example: `{"id":"t8x1","name":"T8","seats":8,"area":"Terrace","shape":"rect","x":20,"y":20,"w":176,"h":76}`

Live table status is separate: `S.ts[tableId]` is one of `free` (default if missing), `seated`, `dessert`, `paying`, `clearing`.

**Room**: just a string in `S.rooms`. A room exists if it is in `S.rooms`, or any table or decor item uses it as `area`.

**Decor item** (in `S.deco`): `{"id":"d1","area":"Main room","type":"bar","x":190,"y":150,"w":230,"h":44,"label":"Bar"}`. `type` is one of `wall`, `bar`, `door`, `window`, `plant`, `text`. `label` optional text. Rotating swaps w and h.

**Venue** (`S.venue`): `{"name":"Proview","open":"09:00","close":"22:00","dur":90,"bigFrom":5,"bigDur":120}` : opening and closing time, standard stay minutes, party size counted as large, large-party stay minutes. **New (v58): `S.venue.id`** (for example `"pv-2ic1gmwwoga9q5"`), a random id created once the first time the app loads and kept. It is also stored in its own key `proview-bookings-v1-vid`, so **Reset to sample data keeps the same id**. It is the `venueId` in the venue summary.

**Staff, punches and breaks (the "Punch in" tab, just above Settings)**
- Staff member (in `S.staff`): `{"id":"s1","name":"Alex","role":"Floor","rate":0,"pin":""}`. `role` is one of `Floor`, `Kitchen`, `Kitchen porter`, `Runner`, `Manager`, `Other`. `rate` is hourly pay in pounds (0 = use `S.fc.rate`). `pin` is an optional 3 to 6 digit code (plain text, stops mistakes, not real security).
- Punch (in `S.punches`): `{"id":"p1","staff":"s1","in":1793900000000,"out":1793925000000,"br":[{"s":1793910000000,"e":1793911800000}]}`. `staff` is a staff id; `in` and `out` are millisecond timestamps; `out` is `null` while the person is still on shift. **New: `br`** is an optional list of breaks, each `{s,e}` ms timestamps; `e` is `null` while the break is running. A shift is counted on the day of `in`. One open punch per person at a time. Punching out ends a running break automatically.
- **Breaks are unpaid:** hours worked and pay = (out − in) − breaks. A manager can correct break minutes when editing a punch (stored as one break in the middle of the shift).
- Staff view of the tab: each person's card with Punch in / Start break / Finish break / Punch out (PIN asked if set), who is on shift and on break. **Nothing about pay is visible to staff.**
- Manager view (after PIN): staff and hourly rates list (including people who have never punched), Add staff / Edit rate, rota upload, hours-this-week table with pay estimate, punch list with edit, delete and "add a missed punch", labour cost today.
- Privacy: staff names, pay rates, hours and rotas are **never** part of the venue summary.

**Manager lock (new, v42).** Pay rates, labour cost, sales figures and the planned-labour numbers are hidden until a manager signs in with `S.mgrPin`. First use asks to set a PIN. It locks again after 10 minutes of no use or with the Lock button; 5 wrong tries pause sign-in for 30 seconds; a forgotten PIN cannot be recovered. **This is a screen lock only, not security**: the data is still in the browser. Real protection needs manager logins on a server. Hidden from staff: Punch in hours/pay/rates/history and all staff edits; Settings labour block (staff cost per hour, spend per guest, target labour %); Reset to sample data; Reports Outlook planned labour and labour/sales guidance; Reports History sales, labour and labour % columns and the "Add past figures" box; Staff still see guest numbers and suggested staffing numbers.

**Rota (new, v44).** Manager uploads an Excel (.xlsx) or .csv rota on the Punch in tab (names down the left, Mon to Sun or dates across the top, cells like `9-5`, `7am-3pm`, `10:00-17:00`; blank or OFF = day off; Floor and Kitchen sections in one sheet are fine; old .xls is not supported). A preview is shown, the week start can be chosen if the file only has day names, then it is saved to `S.rotaSh`: array of `{"n":"Duygu","d":"2026-11-09","s":420,"e":900}` where `n` = name as written in the rota, `d` = date, `s` and `e` = minutes after midnight. Uploading replaces shifts for the dates covered and keeps other weeks; shifts older than 60 days are dropped. Names are matched to `S.staff` by full name, else first name; unmatched people use the default rate `S.fc.rate`. Planned labour for a day = sum of shift hours × rate. Rota hours are treated as paid hours (no break deducted). Reports, Outlook shows rota labour for today/tomorrow to managers, or the old estimate labelled "suggested, no rota uploaded".

**Loyalty scheme (new, v48 to v52).** `S.loy = {"on":true,"n":3,"pct":10,"code":false,"used":{"07700 900131":1}}`.
- Rule: a guest key's **confirmed visits** `V` = number of bookings with `status:"done"` AND `left` set. Rewards earned = floor(V / `n`). Rewards available = earned − `used[key]`. No-shows, cancellations and auto-completed or "Complete"d bookings never count.
- A booking of a guest with a reward available shows an amber "10% loyalty discount due" label; staff press **Apply 10% discount** (sets `disc`, optionally `code`, increments `used[key]`); **Undo discount** reverses it. The printout shows "10% loyalty due".
- `S.loy.code` (operator toggle, off by default): when on, each earned reward comes with a code `PV-` + 5 characters, worked out from the guest key and reward number (FNV hash, so not secret and the same every time). The Guests page, Loyalty tab and guest window show the code and a ready-written thank-you message with an "Email this" (mailto) button when an email is known. Nothing is sent automatically.
- Where to find it: **Guests, Loyalty tab** (settings, summary tiles, regulars list). Settings has a short pointer card.
- Intended future behaviour (not built, needs a server): bookings made online (Google, website) give the guest's email; if the restaurant's toggle is on, a real, unguessable discount code is emailed automatically when a visit is confirmed with Left, and the code is validated when the guest books or arrives.

**Settings**
- Auto-complete: `S.auto` (number of minutes after booking time when seated bookings become `done`; 0 off; default 120).
- Labour and forecasting: `S.fc = {"spend":22,"rate":13.5,"perStaff":8,"minStaff":2,"target":30,"typical":0}` : average spend per guest (pounds), staff cost per hour (pounds), guests per staff member, minimum staff on shift, target labour as % of sales, typical guests per day (0 = estimate). Manager only.
- Colours: in the separate `-colors` key (main, bg hex codes).
- History: `S.hist = {"2026-10-31":{"c":112,"s":2650,"l":790}}` keyed by date; `c` covers (guests), `s` sales in pounds (optional), `l` labour cost in pounds (optional).
- Layout: Settings cards are in two balanced columns (left: Colours, Venue, Auto-complete, Loyalty pointer; right: Tables, Manager access, labour settings).

**Reports, Outlook (changed v44):** forecast now stops at **tomorrow** (today and tomorrow only), because further ahead is guesswork without a lot of history. Tiles: Today, Tomorrow, planned labour tomorrow (manager) or suggested staff hours (staff).

# 7. VENUE SUMMARY FORMAT (built into Backoffice v3; the customer app should produce exactly this)

One JSON object, shown as text the owner can copy (Settings, "Export venue summary", with a Copy button). The Backoffice only reads the fields below and ignores anything else, so guest details must simply never be put in it.

| Field | Type | Notes |
|---|---|---|
| format | string | `"proview-venue-summary-1"` |
| venueId | string | a random id the customer app creates once and keeps (e.g. in `S.venue.id`), so the Backoffice recognises the same restaurant on re-import. Without it the Backoffice matches by venueName |
| venueName | string | **required.** `S.venue.name` |
| appVersion | string | **required.** `"v214"` (the app keeps one version constant, `APPV`) |
| lastActive | string | ISO date-time of the export, e.g. `"2026-11-06T09:30:00Z"` |
| openingHours | object | `{"open":"09:00","close":"22:00"}` from `S.venue` |
| rooms | array of string | `S.rooms` |
| tables | array | each `{id,name,seats,area,shape,x,y,w,h}` exactly as in `S.tables` (fill in derived shape and size if missing) |
| decor | array | each `{area,type,x,y,w,h,label}` from `S.deco` |
| bookingsToday, bookingsNext7Days, bookingsLast7Days | number | counts, excluding `cancelled` |
| guestsLast30Days | number | sum of party sizes of bookings that were `seated` or `done` |
| noShowRateLast30Days | number | percent, 0 to 100 |
| averagePartySize | number | |
| bookingSourceSplit | object | `{"Phone":n,"Website":n,"Walk-in":n,"App":n}` |
| errorCountLast7Days | number | 0 until errors are tracked |
| storageOk | boolean | false if saving to the browser failed |
| loyalty | object, optional | `{"on":true,"n":3,"pct":10,"codeOn":false}` (settings only) |

**How v58 fills these fields (the Backoffice should expect this):** `rooms` = all rooms (from `S.rooms` plus any room a table or decor item uses); every table has shape and size filled in; `decor` w/h filled from defaults if missing; counts leave out `cancelled` bookings. `bookingsToday` = today. `bookingsNext7Days` = tomorrow up to and including 7 days ahead. `bookingsLast7Days` = the 7 days before today (not today). `guestsLast30Days` = guests in bookings that are `seated` or `done`, from 30 days ago up to today. `noShowRateLast30Days` = no-shows divided by (seated + done + no-shows) over the same 30 days, as a percent with one decimal (0 if none). `averagePartySize` = average party size of non-cancelled bookings in the same 30 days, one decimal. `bookingSourceSplit` = counts in the same 30 days. `errorCountLast7Days` is always 0 for now. `storageOk` is a real test: the app tries a small save in the browser. `loyalty` = settings only (`on`, `n`, `pct`, `codeOn`). `lastActive` = the time of the copy, so press Copy again for fresh figures. The summary contains no guest names, phones, emails, notes, staff names, pay, rotas, punches, PINs or reward codes (checked in a test with a manager PIN, an email and a reward code present).

Backoffice rules: a new venue starts on the 14-day trial; importing the same venue again updates its figures and floor plan; health shows "Needs a look" if errorCountLast7Days is above 0 or storageOk is false. Imported venues are skipped by release roll-outs (the Backoffice cannot push to them yet).
